loam

Loam has Claude Code work on your issues in the background, until your checks pass.

Each run works in its own worktree. When its checks pass, Loam opens the pull request and reads CI. You decide twice: when you approve the plan, and when you merge.

$curl -fsSL https://raw.githubusercontent.com/GregorMcC/loam/main/scripts/install-release.sh | sh
Install Loam View on GitHub

macOS 26 or later on Apple silicon, with Claude Code. The GitHub CLI opens the pull requests.

The line

From an issue to a merged pull request

A run is one goal that a background Claude Code session works on in its own worktree, until its checks pass. The line shows the runs of each plot by station. You decide at Shape and at Land, and Loam does the steps between them.

Station 1

Intake

Intake lists the open work of a plot. It reads the GitHub issues of the plot's repos through gh, the Linear issues of its Linear team and project links, and the tickets of a map.md file in its links. Filters show only the issues assigned to you, or the Linear issues in the current cycle.

Select items and press ⌘↩ to send them to Shape. Start as a chore skips Shape: you write the goal and the Done when checks, and the run starts now.

  • X Select an item
  • ⌘↩ Shape the selected items

Station 2

Shape

Claude reads the repo and drafts the run: a goal, a plan, the assumptions that it made, and the Done when checks. Each check is a shell command that passes when it exits 0 in the worktree.

You approve the draft, or ask Claude to change it. An issue that needs changes in more than one repo can split into a group of runs, one in each repo.

  • A Approve, then go to the next item
  • C Ask Claude to change it
  • N Not now: the run ends, and the issue stays open

Station 3

Run

Loam makes a worktree and starts a background session with claude --bg. The session gets the seed of the plot. It works in Claude Code's auto permission mode, because nobody is there to answer a prompt.

Each time the session ends a turn, the gate runs the Done when checks and the plot's rules in the worktree, and checks that the work is committed. A failed check goes back to the session as its next try. When the tries run out, the run stops and comes to your desk.

Ship notes

Walkthrough
What changed and why, in 2 to 4 plain sentences.
Files in reading order
Each changed file once, with its role. Loam checks the list against the diff and adds any file that Claude left out.
Risk
Low, medium or high, with reasons. Loam adds its own facts, such as a store migration, a changed dependency file, or a file that the plan did not name.

Station 4

Ship

When every check passes and the repo is on GitHub, Loam pushes the branch and opens the pull request. If the repo has a PR template, Claude fills it in. A run in a repo that is not on GitHub goes straight to Ready.

Loam then reads CI on the pull request. A failed CI check goes back to the session as a try, with the end of its log, and the fix goes to the same pull request.

Station 5

Land

The run is Ready. At the desk you read the walkthrough, the files in order, the diff, the evidence from the checks and CI, and the risk.

Add a note to a line and send the run back. The session resumes with your notes, and the gate and CI run again. Or merge: Loam merges a run only when you choose Merge.

After the merge, Loam can remove the worktree and the branch, move the Linear issue to Done, and move Where it stands on.

  • ⌘↩ Merge
  • S Send back
  • ] Next file

Control

Runs work inside the limits that you set

Runs spend your Claude Code usage. The limits set how much they can spend, and how many run at once.

Limits and the usage hold

By default, 3 runs work at a time and a run can take 40 turns. Each run gets 3 tries, and the chore start form can change that. A run over the limit waits in Queued, with a note such as "Waits for a slot".

The usage hold reads the week's Claude Code usage. At 80% by default, new runs wait in Queued until the usage drops or the week starts again. A turn limit or a hold of 0 turns it off.

Each plot can have a model and an effort for its runs. The chore start form sets them for one run.

Updates to Linear

Each update that Loam makes to a Linear issue has its own switch. Loam can move the issue to In Progress when a run starts, attach the pull request, and move the issue to Done when the run lands.

It can also post the walkthrough as a comment. That switch is off by default. A write to Linear that fails never stops a run.

Recurring runs

A recurring run starts on a timetable, such as weekdays at 06:30. A precheck decides if there is work. With no work, the run is Skipped, and no session starts.

A Shape recurring run drafts a run for you to approve. A chore runs to its gate and waits for you to land it. A recurring run starts nothing while a run that it started has not ended.

Rules

A rule is a check that every run of a plot must pass, such as "Views use the colour tokens". When you send back a note like one that you sent back before, Loam offers to make it a rule.

The tick

loam tick starts the recurring runs that are due, ships the runs whose checks passed, and starts queued runs. loam tick install has launchd run it every 5 minutes while you are logged in, so runs move when the app is closed.

Stopped by a limit

When Claude Code stops a session at a usage limit, the run shows Stopped by a limit and counts no try.

Runs from the CLI

Each step has a command, such as loam run start, loam run approve and loam run land. The app uses the same commands. A run with no issue starts from the CLI.

The terminal half

Every run starts knowing the work

Loam is also a macOS terminal built on libghostty. It keeps each area of work in a plot. Each run and each interactive session starts with the brief, the repos and the links of its plot.

Brief
Three short parts. What and Why rarely change. Where it stands moves with the work. WhatWhyWhere it stands
Repos
Local git checkouts. One is the main repo, where sessions start. A repo can belong to many plots.
Links
Labelled pointers to Notion pages, Linear issues, GitHub, notes, URLs, and local folders. A seed holds the links, never their content.
Worktrees
Separate checkouts of a repo, each on its own branch. Each run gets one. Loam runs your setup command in each new worktree.
Change log
Every edit to the plot, by you or by a session, with who made it and when. Undo adds a change. It never removes one.

Seeded sessions, side by side

Press ⌘T for an interactive Claude Code session with the seed of the active plot. The sidebar shows each plot as a tree of repos, worktrees and panes.

  • Needs you: the session waits on your answer.
  • Done, unread: the session finished a turn that you have not seen.
  • ⌘T New seeded session
  • ⌘L Next pane that needs you

Review what Claude changed

The plot panel holds the brief, the repos, and the links. You can edit all of them. When a session changes the plot, the change shows under New since you looked, with the words that Claude removed and added.

The change log keeps every change. Undo reverses one change. An undone change stays in the log.

  • ⌘I Show or hide the plot panel

Go anywhere from the keyboard

The quick switcher finds plots, panes, links, and commands. Actions lists what you can do in the active plot. Each plot also has its own key.

  • ⌘P Quick switcher
  • ⌘J Actions
  • ⌃1 to ⌃9 Go to a plot

Your terminal, in your theme

Loam runs on libghostty, so your Ghostty config applies: the font, the keys, and the theme. The window takes its colours from the terminal theme and changes when you reload the config. With no config, Loam uses its own Night and Day themes.

Your layout comes back

Quit and reopen Loam, and your tabs and splits come back. Each session resumes when you show its plot.

The CLI works in any terminal

Use loam start in Ghostty or any other terminal to start a seeded session without the app. The MCP server lets each session read and update its plot.

Worktrees that you make

A worktree that you make by hand shows its ship state, from Not pushed to Merged, and lands from the Land sheet. Ship state is information, so it raises no alert.

GitHub through gh

Loam reads and changes GitHub only through the GitHub CLI, and it holds no GitHub credentials. Without gh, or when you are signed out, Loam shows local state and says how to fix it.

Design

The decisions behind the design

Each decision about plots and sessions has a record in the repo, with the options that I rejected and the reasons. The decisions about runs link to the contract, which says what the core does.

The gate runs your checks

A run ends its work when your checks pass in its worktree and the work is committed. What Claude says about its work does not count. The gate is the session's Stop hook, so a failed check goes back at once as the next try.

Contract: Runs

You merge

Loam opens the pull request and reads CI, then stops at Ready. A run lands only when you choose Merge at the desk, or when the pull request merges on GitHub.

Contract: Land

Rules live outside the worktree

Loam keeps the rules of a plot in its store. A run cannot change a rule to make its own work pass.

Contract: Rules

The Linear key stays in the Keychain

Loam keeps your personal Linear API key in the macOS login Keychain, and only the core reads it. A pull request names the issue key and no Linear URL, because the repo can be public and the workspace private.

Contract: Linear

A seed holds links only

Loam never fetches or caches the content of a linked page. A link is always current, and no work content goes to disk. Claude fetches a page through its own connectors when the task needs it.

ADR 0001

Sessions start in the main repo

Claude Code applies only the settings of the folder where a session starts. A session in the main repo keeps its permissions, hooks, and git status. The plot folder, with the seed, and the other repos attach as added folders.

ADR 0003

The core works without the app

The loam CLI and the MCP server hold the plots, start seeded sessions, and move runs. You can use them in any terminal. The app is one front end to the core.

ADR 0002

The CLI is the contract

The core is one Go binary. The Swift app reads and changes plots and runs only through loam --json, with stable exit codes. The two sides share no code.

ADR 0004
Install

Install Loam

One script installs the Loam app and the loam CLI.

  1. Run the install script

    Paste this command in a terminal.

    $curl -fsSL https://raw.githubusercontent.com/GregorMcC/loam/main/scripts/install-release.sh | sh

  2. Connect Loam to Claude Code

    Run this command once. It registers the Loam MCP server with Claude Code.

    $loam setup

  3. Start your first plot

    Open Loam. Press ⌘N and name the plot. Add the repos, and a Linear team or project link if you use Linear. Write the brief in the plot panel.

  4. Start your first run

    On Today, press ⌘R to open Intake. Select an issue with X and press ⌘↩. Claude drafts the run, and the draft comes to your desk.

  5. Let runs move while Loam is closed

    This command is optional. It has launchd run loam tick every 5 minutes while you are logged in.

    $loam tick install

Requirements

  • macOS 26 or later
  • A Mac with Apple silicon
  • Claude Code, with claude on your PATH
  • For Ship and Land: the GitHub CLI (gh), signed in. Loam opens pull requests and reads CI through it.
  • Optional: a Linear personal API key, for Linear issues in Intake and updates to Linear. Add it in Settings.

Update

Run the install command again. If Loam runs, the script quits it, installs, and opens it again. If a session is in a turn, Loam asks first, and the script waits up to 10 minutes.
